# 用語集

reco は、設定ファイルに書いた欲しい状態と GitHub 上の実際の設定を比べ、変える予定を示し、利用者の承認を得てから設定を変えます。この流れに沿って、宣言、確認、計画、適用の順に、ユーザーガイドで使う用語を並べます。各用語には平易な言い換えを添え、reco の出力に現れるものは、出力のどこに現れるかも示します。

## 宣言に関する用語

設定ファイルに書く内容を指す用語です。

- **設定宣言**：設定ファイルに書いた、リポジトリごとの欲しい状態の集まり。変更予定があるときの `plan` と `apply` の出力では、先頭の `Configuration:` の行に設定ファイルのパスが出る
- **リポジトリごとの宣言**：設定宣言の要素で、一つのリポジトリの名前と、そのリポジトリの欲しい状態の組。設定ファイルでは `repositories` の下に並べる一つひとつの項目に当たる
- **管理設定**：あるリポジトリについて、設定ファイルに値を書いた設定
- **管理範囲**：あるリポジトリの管理設定の集まり。リポジトリごとに決まり、ほかのリポジトリとは共有しない
- **未管理設定**：あるリポジトリの管理範囲に入っていない設定。設定ファイルに書かなかった設定と、reco の設定ファイルに書けない設定の両方を指す
- **期待値**：一つの管理設定について、設定ファイルに書いた値。`plan` の出力では、`->` の右側か `Desired:` の行に出る
- **期待状態**：あるリポジトリの管理設定についての欲しい状態で、管理設定ごとの期待値からなる
- **設定グループ**：意味を確定するために、複数の値をまとめて一つの期待値として書く設定。設定ファイルに書いたリポジトリでは、全体で一つの管理設定になる。reco では `actions.permissions.selected_actions` の3項目（`github_owned_allowed`、`verified_allowed`、`patterns_allowed`）がこれに当たり、`plan` と `apply` の出力でも3項目をまとめて `actions.permissions.selected_actions` の一つの設定として示す
- **Actions 許可ポリシー**：実行を許可する Actions と再利用可能なワークフローの範囲を定める設定。設定ファイルでは `actions.permissions.allowed_actions` に書く

## 確認に関する用語

reco が GitHub から設定を読み取って確かめる場面の用語です。

- **現在状態**：GitHub 上に実際にある設定の状態。reco が読み取って確かめられた部分（観測結果）とは区別する
- **観測**：reco が、ある時点に GitHub から設定を読み取って確かめること
- **観測結果**：一回の観測で確かめられた設定の情報。`show` の表示と、`plan` の `->` の左側や `Current:` の行に出る値は、観測結果を示したものである
- **観測不能**（`unavailable`）：観測はできたが、GitHub の取得条件（例：Actions が無効なリポジトリでは Actions 許可ポリシーを返さない）のために、ある設定の値を確かめられないこと。出力では `unavailable (理由)` と示し、reco は値を推測しない
- **観測操作の失敗**：認証、権限、通信などの問題のために、観測そのものができなかったこと。出力では `unavailable` ではなくエラーとして示す

## 計画に関する用語

期待状態と観測結果を比べ、変える予定をまとめる場面の用語です。

- **比較不能**：管理設定の値が観測不能のため、期待値と同じか違うかを判断できないこと
- **変更予定**：期待値と違うと確かめた管理設定か、比較不能な管理設定。確認済みの差分と比較不能な設定予定に分かれる
- **確認済みの差分**：値を確かめられ、期待値と違うと分かった変更予定。`plan` の出力では、観測した値と期待値を `->` でつないで示し、`Plan:` の行の `known change` の数に数える
- **比較不能な設定予定**：比較不能だが、期待値にする予定の変更予定。`plan` の出力では `Current: unavailable (理由)` と `Desired:` の行で示し、`Plan:` の行の `not-comparable setting` の数に数える
- **副作用**（`Side effect:`）：宣言した変更を行うと GitHub の仕様によって避けられずに起きる、未管理設定の値の消失や変化。副作用を生む変更予定の最後に `Side effect:` の行で示し、承認の対象に含める
- **変更計画**：対象にしたリポジトリごとに、管理設定を比べた結果と変更予定をまとめたもの。`plan` が表示し、`apply` は承認を求める前に同じ形で表示する

## 適用に関する用語

承認を得て GitHub の設定を変え、その結果を示す場面の用語です。

- **承認**：`apply` が示した変更計画について、利用者が端末の対話で与える明示的な同意で、その一回の `apply` で示した対象と変更内容にだけ及ぶ。承認を求める行は `Apply these changes? [y/N]:` である
- **論理的な設定変更**：一つ以上の変更予定をまとめた、完了したかどうかを判断する変更の単位。`apply` の結果を論理的な設定変更ごとに並べるとき、二つの変更予定をまとめたものは、二つの管理設定の名前を ` + ` でつないで示す
- **更新操作**：GitHub の設定を変えるために reco が送る、個々の更新要求。一つの論理的な設定変更が二つの更新操作からなることがある。失敗（`failed`）した論理的な設定変更では、出力の `Update request` の行に、更新操作ごとの結果（始めなかった更新操作は `not started`）を示す
- **成否不明**（`unknown`）：更新操作について、GitHub が受け付けたとも拒否したとも確かめられないこと。出力では `Update request` の行に `unknown` と示す
- **変更前提**：承認した変更の更新操作を始めてよいかを、その直前に確かめる条件。対象が承認したリポジトリと同じであることや、関係する設定の値が承認したときに予定した値から変わっていないことなどからなる。値が変わっていて成り立たなかったときは、出力の `Precondition:` の行で示す
- **中間状態**：二つの更新操作からなる論理的な設定変更で、一つ目の更新操作で GitHub の設定が変わり、二つ目の更新操作による変更がまだない状態。出力に専用の表示はなく、失敗（`failed`）したときは、`Update request` の行で、どの更新操作まで終えたかを確かめられる
- **変更対象外の設定**：論理的な設定変更の更新操作で影響を受け得るが、その論理的な設定変更が変える対象に含めない設定
- **変更対象外の設定の予期しない変化**：変更対象外の設定の値が、更新の前後で変わっていたこと。出力では `Other settings:` の行で示し、reco は原因を断定しない
- **変更結果**：論理的な設定変更ごとの終わり方で、完了、失敗、未実行のいずれか。`apply` の出力では、これらをリポジトリか論理的な設定変更の行に次の語で示す
- **完了**（`updated`）：必要な更新操作の成功と期待状態との一致を確かめ、変更対象外の設定の予期しない変化も見つからなかったこと
- **失敗**（`failed`）：更新操作を始めたが、完了を確かめられなかったこと
- **未実行**（`not attempted`）：更新操作を一つも始めなかったこと
- **変更不要**（`no change`）：リポジトリの管理設定がすべて期待値と一致していて、更新が要らないこと。変更結果ではなく、変更計画を作るときに確かめた事実である
