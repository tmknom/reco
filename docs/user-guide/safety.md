# Safety

## 書いていない設定を変えない

reco が変えるのは、設定ファイルに書いた設定だけです。たとえば `allow_auto_merge` だけを書いたリポジトリでは、reco が GitHub に送るのは `allow_auto_merge` の値だけで、リポジトリの名前や説明などのほかの設定は送りません。

Environment も同じです。reco が作成するのも、`deployment_branch_policy` を変えるのも、設定ファイルに名前を書いた Environment だけです。Environment を削除することはありません。

例外は、書いた設定を変えると GitHub の仕様でほかの値が消えるか変わる場合です。たとえば、`allowed_actions` を `selected` から `all` や `local_only` に変えると、GitHub が `selected_actions` の値を消します。`dependabot_alerts` を変えると、GitHub は Dependency graph も同じ値（有効か無効）に変えます。`dependabot_alerts` を無効にするときは、設定ファイルに書いていない Dependabot security updates も、有効だったなら無効にします。reco はこれらを変更計画の `Side effect:` の行に示し、その内容も含めて承認を求めます。

## すべてのリポジトリを読み取ってから更新を始める

`apply` は、承認を求める前に、設定ファイル全体を読み、対象のすべてのリポジトリの設定を GitHub から読み取ります。設定ファイルに誤りがあるか、読み取れないリポジトリが一つでもあれば、どのリポジトリも更新せずに止まります。

読み取ったあとで、安全に変えるための条件が成り立たない変更（変更計画の `Applicability: not applicable` の行が付いた変更）が一つでもあれば、承認を求めず、どのリポジトリも更新せずに止まります。このとき reco は、そうした変更をすべてのリポジトリについて変更計画にまとめて示します。

## 承認した内容だけを変える

`apply` は、変更計画を表示して承認を求め、承認されるまで設定を変えません。承認のあとで、対象のリポジトリや変更の内容を差し替えることもありません。

## 承認のあとで設定が変わったら止まる

reco は、更新の直前ごとに、関係する設定が承認したときの値のままかを確かめます。Environment を作成するときは、同じ名前（大文字と小文字だけが違う名前を含む）の Environment がまだないことを確かめます。承認のあとでほかの人や仕組みが設定を変えていたり、同じ名前の Environment が作られていたりしたら、その更新もそのあとの更新も始めずに止まります。それでも、`apply` のあいだに設定を変えられると、reco が見つけられないことがあります。`apply` のあいだは、同じリポジトリの設定をほかの手段で変えないようにします。

## 問題が起きたら、それ以上更新しない

更新の失敗や、更新のあとの値が設定ファイルのとおりでないことなどを見つけたら、reco は残りの変更も、あとに並ぶリポジトリも更新しません。

## 反映を確かめてから完了とする

GitHub が更新を受け付けただけでは、reco は完了（`updated`）としません。設定を読み直して、設定ファイルのとおりになっていることと、reco が読み取る設定のうち変えようとしていないものが変わっていないことを確かめてから完了とします。

## トークンを表に出さない

reco は、渡されたトークンを GitHub へのアクセスにだけ使います。トークンをファイルに保存せず、出力やエラーにも表示しません。

## reco がしないこと

- **変更を元に戻さない**：`apply` が途中で止まっても、すでに反映した変更はそのまま残る。元に戻すときは、元の値を書いて `apply` する
- **成否が分からない更新を送り直さない**：GitHub が更新を受け付けたか分からないときは、送り直さずに止まる。`plan` で今の値を確かめてから `apply` し直す
- **リダイレクトに従わない**：名前を変えたか移転したリポジトリを古い名前で指定すると、意図しない宛先へトークンを送らないよう、エラーで止まる

`apply` が止まったときにすることは [Troubleshooting](troubleshooting.md) にあります。
