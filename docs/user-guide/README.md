# reco ユーザーガイド

reco は、GitHub リポジトリの設定を YAML で宣言し、現在の設定との差を示して、承認を得てから変更する CLI です。このガイドは、GitHub の個人アカウントで複数のリポジトリを持ち、リポジトリの設定画面の項目をある程度知っている人に向けて、reco の使い方を目的ごとに説明します。Go や GitHub REST API の知識は前提にしません。

## 目的から選ぶ

読者の目的ごとに、読む文書を示します。リンクのない文書は、まだ書かれていません。

| 目的 | 読む文書 |
|---|---|
| reco が何を解決し、自分の環境と設定に使えるかを判断したい | reco の概要 |
| reco に設定の変更を任せて安全かを判断したい | [reco の安全性の約束](safety.md) |
| reco を入れ、必要な権限のトークンを用意したい | インストールと認証の準備 |
| 最初の1回を安全に試したい | はじめての適用 |
| 欲しい状態を YAML にどう書くか、書かなかった設定がどうなるかを知りたい | [設定ファイルの書き方](configuration.md) |
| コマンドとオプション、承認、終了コードを調べたい | [コマンドリファレンス](commands.md) |
| `plan` と `apply` の出力の各行が何を意味するかを知りたい | 変更計画と変更結果の読み方 |
| リポジトリを増やす、対象を絞る、定期的に確かめる、管理をやめる方法を知りたい | 複数リポジトリの運用 |
| エラーのあとや、`apply` が途中で止まったあと、何を確かめて何をすればよいかを知りたい | 困ったときは |
| 出力や文書に出てくる用語の意味を確かめたい | [用語集](glossary.md) |

## 仕様との関係

このガイドは reco の仕様を目的に沿って説明するもので、規則は仕様が定めます。ガイドで足りない条件や例外は、各文書の末尾の References に挙げた仕様で確かめられます。ガイドと仕様が食い違う場合は仕様が優先するため、見つけたら Issue で知らせてください。
