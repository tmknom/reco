# Research

## 目的と適用範囲

本ディレクトリでは、reco が利用する外部仕様を公式資料から抽出し、整理した文書を管理します。現在の対象は GitHub.com REST API であり、以下ではこれらの文書をまとめて **GitHub API 仕様** と呼びます。GitHub API 仕様が扱うのは、reco が利用するエンドポイントの外部契約と、それらに共通する認証、API バージョン、リダイレクト、失敗応答、レート制限、条件付きリクエストです。

## 記述の前提

記述は、GitHub REST API `2026-03-10` 版と、版を持たない GitHub の公開ドキュメントに基づきます。各セクションの根拠は、そのセクションの Relationship テーブルに示します。公開ドキュメントに記載のない挙動は「記載がない」と明示し、GitHub の保証として扱いません。公開ドキュメントの記載が不十分で、reco の開発者が実際の動作を確認した事項に限り、`> [!NOTE]` の注釈で公開ドキュメントの記載と区別して示します。

## 文書の分け方

GitHub API 仕様は、全エンドポイントに共通する仕様と、エンドポイントの仕様に分けます。エンドポイントの文書は、GitHub REST API ドキュメントのカテゴリのページ（「REST API endpoints for repositories」など）ごとに一つ作り、そのページのエンドポイントについて、必要な権限、HTTP 応答、フィールド、更新結果の確認方法、実際の動作の確認結果を一つの文書にまとめます。サポートする設定項目を増やすときに、変更が原則としてそのページの文書だけで済むようにするためです。

| 変更 | 変更する文書 |
|---|---|
| 既存のページのエンドポイントやフィールドを追加する | そのページの文書 |
| 新しいページのエンドポイントを追加する | 新しい文書を作り、本 README の一覧に加える |
| 全エンドポイントに共通する仕様を追加する | GitHub REST API 共通仕様 |

共通仕様は個々のエンドポイントの文書を参照しません。エンドポイントの文書は、共通仕様とほかのエンドポイントの文書を参照してよいものとします。
